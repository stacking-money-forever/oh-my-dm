# 보안 정책 / Security Policy

[한국어](#한국어) · [English](#english)

## 한국어

### 지원 버전

1.0 이전에는 가장 최근에 릴리스된 버전에만 보안 수정이 제공됩니다.

### 취약점 제보

GitHub 저장소의 **Security → Report a vulnerability** 버튼을 사용해 private security advisory를 제출해 주세요. 공개 issue를 만들거나 실제 쿠키, 세션 파일, DM 내용 또는 개인정보를 첨부하지 마세요.

영향을 받는 버전과 플랫폼, 예상 영향, 개인정보를 제거한 재현 단계, 가능한 완화 방법을 포함해 주세요. 7일 이내에 접수 확인을 보내고 14일 이내에 초기 평가를 제공하는 것을 목표로 하지만, 자원봉사로 운영되는 프로젝트이므로 응답 시간을 보장할 수는 없습니다.

### 범위

브라우저 세션 처리, 로컬 파일 권한, command injection, 손쉬운 사용 자동화, 의도하지 않은 메시지 노출, dependency compromise는 보안상 중요한 영역입니다. 이 프로젝트 밖의 플랫폼이나 서비스 동작은 해당 vendor의 신고 창구로 안내할 수 있습니다.

## English

### Supported versions

Until 1.0, only the latest released version receives security fixes.

### Reporting a vulnerability

Please use GitHub's **Security → Report a vulnerability** button to submit a private security advisory. Do not open a public issue and do not attach real cookies, session files, direct messages, or personal information.

Include the affected version, platform, impact, reproduction steps with sanitized data, and any suggested mitigation. You should receive an acknowledgement within 7 days. We aim to provide an initial assessment within 14 days, but response time is not guaranteed for this volunteer-maintained project.

### Scope

Security-sensitive areas include browser session handling, local file permissions, command injection, accessibility automation, unintended message disclosure, and dependency compromise. Platform or service behavior outside this project may be redirected to the relevant vendor.
